Outcome đã chốt

Không có catalog replica. Không có client monetary authority. Không có auth tạm thời, payment provider, delivery grant, cart hoặc multi-line Order.

01 · Storefront

App độc lập

Static assets riêng. Chỉ gọi configured Nexus API. Không nhận D1/R2 binding.

02 · Worker authority

Catalog, price, transaction

Resolver hiện có xác thực selection. Captured Product revision bảo vệ snapshot khỏi concurrent catalog edit. D1 batch commit hoặc rollback full aggregate.

03 · Safe projections

Customer + Console

Customer thấy purchase-time selection và payment next-step. Console demo thấy operational fields. Cả hai đều không thấy delivery/capability secrets.

Ba user flows

UI không sửa server truth. Mỗi flow kết thúc ở persisted projection từ Worker.

  • MoneyBrowser sends identity and quantity only. Worker derives unit price, amount, total, currency.
  • CapabilityWeb Crypto value travels in an explicit header. Reopenable URL retains it only after #.
  • IdempotencyRetry keeps the same caller-held idempotency identity and capability. One Order aggregate survives.

Implementation roadmap

Five gated phases

Rủi ro được khóa trước code

Red-team gate đã thay đổi plan tại ba điểm P1: capability retry, snapshot concurrency, và token transport.

  • P1 · RetryCapability do Storefront tạo và giữ trong retry state. Idempotency retry dùng lại đúng capability; server chỉ giữ digest.
  • P1 · SnapshotResolver trả Product revision cùng snapshot. Batch có final failing assertion cho exact revision đó; catalog edit xen kẽ rollback toàn bộ aggregate.
  • P1 · URL leakCapability không ở path/query. Private route dùng fragment, page chuyển giá trị đó sang one allow-listed request header.
  • P1 · CORSKhông reflect Origin, wildcard, credential CORS hoặc Console CORS. Allow-list chỉ cho configured Storefront origin và headers cần thiết.

Acceptance boundary

Anonymous Console vẫn là demo risk.

S4 sở hữu identity/permissions. S5 sở hữu payment/delivery. S2 không báo cáo hai capability này là hoàn thành.
